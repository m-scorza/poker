Decision D3 · owner comments 6, 15 · governs UIR-008

Persistent money context —
where, and how restrained?

The owner misses always-visible money. The constraint is the jewel budget: exactly one element per screen may glow, and a shell-level money module would claim that budget on every route including Ranges, Drills and Hands.

Recovered history — the owner is right, this shipped and was deliberately removed

It existed until 2026-06-17. It was removed for lying, not for being wrong.

The sidebar money hero was real. ca7a08b — "fix(ui): remove fabricated stats from sidebar + dashboard (CQ-1)", PR #80, 2026-06-17 — deleted it. The markup was a .jewel block above the hero identity, money-green with a 0 0 20px rgba(52,217,140,0.40) glow, reading:

Lifetime profit
+$388.85
+141.4% ROI · 250 tourneys

Every one of those numbers was a hardcoded literal, sitting beside a fake "Grinder · B+" rating and a hardcoded "scorza23" identity. The commit's reasoning: "for a trust-thesis product, permanently displayed fake numbers are disqualifying." The design was never the problem — the data was.

The commit named its own condition for return. Verbatim: "Computing a real lifetime figure here would add a full-table scan to an always-mounted component — the perf anti-pattern the audit's 1.4 already flags — so the honest minimal fix is to remove the lie; a real figure can come later behind a derived-stats layer."

That derived-stats layer still does not exist. There is no cache, memo table or summary row anywhere in src/data/; DashboardPage.tsx:29–32 still calls db.hands.toArray(), db.heroDecisions.toArray() and db.tournaments.toArray() on mount — 15,245 + 15,245 + 250 rows on the demo dataset. Doing that from an always-mounted sidebar is exactly what #80 refused. So D3 is not a design question. It is: build the derived-stats layer, or don't restore the block.

There is also a live regression guard. src/components/layout/__tests__/Sidebar.test.tsx asserts the sidebar renders no 388.85, 141.4, 250 tourneys or Grinder. Any restoration must keep that test passing by computing real values — not by weakening the guard.

What exists today — verified 2026-08-10

No shell money context at all; two page-local marquees instead

src/components/layout/Layout.tsx and Sidebar.tsx render no financial data. The sidebar's bottom block is a static avatar + hero name + the literal label "Hero". Money appears only inside two page-local marquees: WireTape on Dashboard (PROFIT / VPIP / PFR / 3BET, each item printed twice for the scroll loop) and Ticker on Coach's Note (VPIP / PFR / C-BET HU / REFERENCE MATCH / NOT GRADED / DECISIONS).

Both marquees clip at narrow widths — at 390px the Coach's Note ticker renders its first item as "/PIP 37.5%" with the V cut off, and the trailing "DECISIONS" label is cut mid-word. Leaving Dashboard or Coach's Note means losing every money number entirely; on Ranges, Drills, Hands, Sessions and Villains there is no financial context of any kind.
